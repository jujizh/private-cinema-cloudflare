# 排错：先分清问题发生在哪一层

## 1. 网站打不开或入房超时

首页超时与视频卡是两件事。先分别测试 HTTPS 首页、/api/config、邀请有效期、
WSS 握手及 welcome。能打开首页不保证 WebSocket 可达；Connected 也不保证媒体可用。
复制“Connection report”，它刻意不带邀请码、用户名、聊天和长期密钥；其他日志仍需脱敏。
查看 Worker/DO 日志时先做复现时间标记，不公开 Authorization、Cookie 或邀请链接。
跨国网络、DNS、运营商、代理规则会影响结果，不按国籍判断必然可达或必然被封。

## 2. 为什么两个人仍是 SFU

当前先准备 SFU 并探测直连，ICE/NAT/UDP/代理不合适时可保持 SFU，或 P2P via TURN。
人数少只降低扇出负担，不保证打洞成功；同一 Wi-Fi 成功也不保证跨运营商成功。
看**观看端活动路由**，不要把房主“Host → SFU hot backup”误当成对方一定走 SFU。
本版有重试与切路状态，记录从何时失败，而不是只根据路由名字断言服务有问题。

## 3. 清晰度/帧率下降

同时记录源分辨率/实测采集帧率、发送编码帧率、带宽限制原因、活动路由、观看端
接收/解码/丢帧及网络丢包。轨道 settings 的 frameRate 可能是配置目标，不等于每秒实际产帧。
0% 丢包不能证明没有拥塞/解码压力；`limiter: none` 也不能排除采集/驱动故障。
电影常为 24 fps，不要把保持 30 fps 配置误认为所有画面必须生成 30 个新帧。

手机上 720p 稳定播放可好于不稳定 1080p，但无法无条件同时保证高分辨率、高帧率、
低码率、低延迟和零缓冲。先用有权使用的固定样片测量，不一边改多项参数一边下结论。

## 4. 源标签页在后台掉帧 / Windows 整机失去响应

优先把电影标签页放入独立可见窗口，避免同窗口切标签；关闭不必要的录屏/叠加层，
检查浏览器节能、硬件加速、驱动及 GPU 各引擎。浏览器/显卡/窗口采集问题不等于云端丢包。
外部播放器窗口共享可触发系统图形采集链路，本站独立本地源页可以减少此依赖，
但不能保证修复驱动/高刷新率/显示合成问题。

若 Win、Alt+Tab、输入法甚至安全桌面异常，先保存工作，查看系统事件/可靠性记录及驱动。
总 CPU 30% 或总 GPU 30% 不能排除单线程、视频编解码引擎、DWM 或驱动阻塞。
不要按网络问题盲目租服务器，也不要为了排错删除注册表、关闭安全防护或强制终止系统服务。
Windows 显示刷新快捷键短暂恢复只是线索，不是故障定论；系统故障由用户自行诊断维护。

## 5. 本地源页无声 / 观众无声

先本地试听；源页无声看 docs/AUDIO.md。源页有声但观众无声，确认勾选分享标签页音频、
观众点击播放/取消静音，检查音轨是否已发布。加载外置 M4A 后应使用“外置音量”。
拖动进度短暂掉帧可能是解码重新定位与关键帧恢复；若长时间不恢复再采集诊断。

## 6. 黑屏、卡住与反复刷新

刷新后出现 left/join 可能是人为刷新结果，不是最初故障。应先保存卡住那一刻的
接收端诊断、源端状态、前后时间和路由切换原因。热备可减少切路空窗，不承诺绝无黑屏。
避免多名用户共用同一浏览器资料的会话状态；标签页身份保留于 sessionStorage，
刷新/切网不应该靠 IP 认定新设备，但清站点数据、换浏览器会改变身份。

## 7. 构建、测试与旧文件残留

初始化阶段没有执行 npm，先看平台队列；安装失败看依赖及 Node；检查失败看具体断言，
不要见到 test/media-health.test.js 就删除测试。上传新版不是删除旧仓库的所有未上传文件。
按干净包核对根目录、lockfile、完整 public/src/test 与部署日志，保留绑定/迁移。
Wrangler 本地部署可绕过 Builds 队列，但不会修复应用测试错误、权限错误或网络不可达。

## 报告问题的最小信息

版本 release、两端浏览器/系统、源类型、是否外置音轨、复现步骤、发生时间、
观看端活动路由和关键统计、是否只在后台/跳转后发生。默认不要附真实影片或私人聊天。
不要上传全部浏览器 profile、GPU dump、访问令牌或未经审查的系统日志。
