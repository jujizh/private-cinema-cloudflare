# 开源前检查与旧部署迁移

## 当前交付方式

这是从当前可用功能整理的**干净源码快照**，没有 .git 目录、历史、生产数据或秘密。
工具源码与构建也包含在仓库中。准备开源文件不等于已在 GitHub 发布；
没有代替你更改原仓库可见性、推送提交、创建 Release 或部署。

新仓库最省心：上传本包内部文件到新公开仓库，然后在自己的测试 Worker 验收。
这样不带旧历史；原仓库及线上服务保留，不必为开源立即替换生产环境。
仓库名/项目名默认 Private Cinema，不保证完成商标可用性检索。

## 去个人化不只是改首页

本快照统一了页面/默认昵称/占位符、测试中的示例身份、包名、内部 token issuer、
文档示例及工具说明。部署配置不带原账号/域名。作者署名以集体 contributors 保留。
不会替你更改旧 Git 作者邮箱、历史提交、截图、分支名、Release ZIP、Actions 日志、
Issue、讨论、Fork、缓存或搜索引擎记录。公开之前逐项审查这些位置。

如果要继续使用原仓库，先备份，检查全部分支与标签中的人名、域名、邀请码、历史密钥；
**有密钥先撤销，不是仅删文件**。重写 Git 历史会影响协作者与已有提交引用，
本次没有自动执行。已有公开拷贝不能靠重写保证收回。

## 旧私有发行版升级注意

开源快照的默认 Worker name/域名/账号不沿用旧值，token issuer 改为中性标识。
直接覆盖原站会使旧签名邀请及管理员会话不再被本版接受；应重新登录、创建新房间/邀请，
不要承诺旧链接兼容。最好先部署独立测试 Worker，再安排自己的正式迁移。

若要升级同一 Worker，保留自己的 name/account/domain 配置及所有迁移/绑定，保留秘密，
备份必要管理数据并验证删除/过期策略。不能通过删 Durable Object namespace 迁移。
浏览器可能仍记住旧昵称，按自定义教程只清对应昵称；完整清站点数据可能改变参与者身份。

## 公开发布清单

- 确认你有权把本项目原创代码按 Apache-2.0 授权；如有他人贡献先核对许可。
- 保留 LICENSE、NOTICE、COPYRIGHT、DISCLAIMER、第三方说明；不加“禁止商用”许可附加条款。
- 跑 `npm run check:public`；它是启发式扫描，不是秘密扫描审计认证。
- 审查 git diff、全部历史和附件；启用 GitHub 可用的 secret scanning/push protection 等防护。
- 完整部署到自己的测试 Worker，用自己的六项 secrets，确认免费/付费状态与账单通知。
- 两端验证入房、音轨、字幕、暂停/跳转、P2P/SFU 回退及 30–60 分钟播放。
- 发布 Release 时附源码、修改说明、测试范围、SHA-256；EXE 必须对应可复现源码，不附 FFmpeg。
- 配置仓库描述、Topics、README、Issue 模板/安全私密报告；明确不是官方服务，不提供内容库。
- 若公众运营，另准备隐私政策、运营主体联系、投诉与删除机制、地区合规及内容授权。

## 值得一起公开的补充材料

目前已随包公开：架构取舍、诊断含义、失败案例排错、限额算法、已知边界、
合成字幕样例、Node/浏览器测试、原生工具构建与测试、CI 及安全打包脚本。
它们能帮助使用者验证并维护自己的实例，而不仅是“复制文件碰运气”。

后续可增加弱网自动化、无真实用户数据的长期基准、账单校准脚本、跨平台音频工具、
接收端字幕延迟补偿和可选低开销热备。未实现或未完成验收的能力不在 README 冒充支持。
