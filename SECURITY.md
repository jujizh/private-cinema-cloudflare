# Security model

## What is protected

- The public homepage exposes no room directory.
- The owner console requires a server-verified password and an HttpOnly, Secure, SameSite cookie.
- Invitations are random, signed, expiring, role-scoped, and revocable.
- The server—not the visible button—decides whether someone can publish media.
- WebSocket connections require a one-time ticket valid for 60 seconds.
- Realtime SFU and TURN long-lived secrets never enter browser JavaScript.
- Temporary TURN credentials are available only to an authorized client already connected to that room.
- One active broadcaster is allowed per room; there is no artificial viewer count limit.
- Login, media calls, chat, and reactions are rate-limited.
- Chat and reactions are not persisted.

## Invitation handling

An invitation is a bearer credential: anyone holding it can use its permission until it expires or is revoked. Send links only through a trusted private channel.

- Use viewer links for normal guests.
- Use guest-host links only for people allowed to broadcast.
- Revoke a link if it is forwarded unexpectedly.
- Lock the room after expected guests have arrived.
- End the room when the screening finishes.

The page stores the active invite in `sessionStorage` and removes it from the address bar after opening. It is therefore not sent as a referrer to unrelated pages. Closing that browser tab clears it in normal browser behavior.

## Owner password

Use a unique password, preferably generated by a password manager. The Worker compares password digests and rate-limits repeated failures. Cloudflare Access can be added as a second gate around owner routes, but it is optional because v2 already enforces owner authentication server-side.

If the owner password is exposed, replace `ADMIN_PASSWORD`. If signed invitations must also be invalidated immediately, rotate `APP_AUTH_SECRET` and create fresh rooms.

## Media and privacy

Media goes from the broadcaster to Cloudflare Realtime SFU and then to authorized viewers. It is not end-to-end encrypted against the SFU service. Do not use the project for material that must be hidden from the infrastructure provider.

Local files are selected and played on the broadcaster's device; the app does not upload them for storage. Viewers can still screen-record anything they can watch, so invite only people you trust.

## Remaining operational risks

- Viewer count increases SFU egress and can consume included usage.
- A leaked invite remains usable until revocation or expiry.
- Browser or OS screen-capture behavior may omit system audio.
- DRM-protected services may display a black screen.
- No browser application can prevent an invited viewer from recording the display.
- Cloudflare and the broadcaster's internet connection remain availability dependencies.

Review Cloudflare analytics and Realtime usage periodically. Set account-level billing notifications before hosting a large screening.
